# 유료·구독 출시 전 체크리스트

지시서 5절. **여기 적힌 것은 현재 적용되지 않는다.** 앱에 결제·구독
기능이 없고(C16), 공개된 약관과 방침도 「현재 없음」을 기준으로 쓰여
있다. **이 문서의 문안을 공개 페이지에 먼저 올리지 않는다.**

## 먼저 정할 것 (사업자 결정 — 개발자가 만들어 낼 값이 아니다)

- [ ] 상품 구성과 가격, 결제 주기, 무료 체험 여부와 기간
- [ ] 자동 갱신 여부와 갱신 전 고지 방법
- [ ] 해지·청약철회·환불 운영 기준 (플랫폼 경로 + 사업자 직접 경로)
- [ ] 유료 이용이 끝난 뒤 **기존 기록의 열람·내보내기 정책**
      — 여기서 막으면 약관 제9조와 어긋난다
- [ ] 미성년자 거래 처리
- [ ] 전자상거래법상 표시할 사업자 정보 — **주소 포함**.
      지금 공개 페이지는 상호만 적고 있다. 유료 서비스를 시작하면
      그것으로는 부족하다

## 문서 (시행 전에 함께 고친다 — 하나만 고치면 서로 어긋난다)

- [ ] 이용약관 제8조를 유료 문안으로 교체 (현재 문안은 「기능 없음」 기준)
- [ ] 개인정보처리방침 10항 — 구매 토큰·주문 식별자·상품·권한 상태 중
      **실제로 처리하는 것**을 적는다.
      「Google 이 결제하므로 사업자는 아무 정보도 처리하지 않는다」고
      쓰지 않는다. 반대로 카드정보를 사업자가 받는 것처럼도 쓰지 않는다
- [ ] Play Data Safety 신고 갱신
- [ ] 스토어 등록 정보·앱 설명 갱신
- [ ] 약관 버전·시행일을 올리고 이전 버전을 남긴다
- [ ] 변경 고지: 이용자에게 불리한 변경은 시행 30일 전(운영 기준)

## 구현 (C17)

- [ ] 구매 보류(PENDING)·성공·취소·갱신·만료·환불 각각의 화면 상태
- [ ] 재설치·기기 변경 시 구매 복원
- [ ] `acknowledgePurchase` 누락 시 자동 환불되는 문제
- [ ] 구매 토큰 검증 경로 — 서버를 두는지 여부부터 정한다.
      **약관을 맞추려고 서버를 새로 만들지 않는다**(지시서 §1.2.4).
      서버를 둔다면 방침의 「자동 전송 없음」 문장이 전부 달라진다
- [ ] 결제 상태와 이용권이 어긋나는 경우의 처리
- [ ] Play 테스트 환경에서 보류·성공·취소·갱신·만료·환불·복원 시험.
      실제 이용자에게 시험 과금을 발생시키지 않는다

## 이 순서를 지킨다

1. 사업자 결정 → 2. 구현 → 3. 테스트 환경 검증 → 4. 문서 동시 개정 →
5. Data Safety 갱신 → 6. 출시

**문서를 먼저 올리고 구현을 나중에 하지 않는다.** 없는 기능을 있는 것처럼
게시하는 것이 Play 정책 위반이고, 되돌리는 비용이 더 크다.
